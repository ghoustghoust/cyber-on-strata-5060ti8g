# 02 · 死循环与卡死 —— 我们怎么治的

> **这一册解决什么**：看起来"卡住/不干活"的三类退化 —— ① **逐字复读** ② **整段复读**（思考不收敛）③ **纯工具轮空壳**；外加一类**不是循环、但看起来像卡死**的：**引擎的 20 秒看门狗开火**。
> **出处（一个事实一个出处，本册只提炼）**：
> - **引擎/服务侧的实现**：`serve/server.py`（`reasoning_loop_recovery`、`reasoning_repeat_coverage`、`repeat_stop_tokens` 收尾打印）
> - **上游对应提交**：`serve: the reasoning loop check also sees a loop written as one long word (#1753)`；引擎内那两处 20 秒看门狗见我们的台账 `坑-引擎20秒看门狗-20260929.md`
> - **平台侧那一半**：同目录 `01-工具调用与重复调用-防治.md`（含 DSH 报告原件）
> 证据等级：代码与常量来自源码（`B`）；看门狗的行为来自我们 2026-09-29 的实测台账（`A`，那一轮机器与件）。

---

## §1 三种形态（先分清是哪一种，处方不同）

| 形态 | 长什么样 | 谁管 |
|---|---|---|
| ① **逐字复读** | 同一个 token 连着吐很多遍（`run_len`） | **引擎自带守卫**（一直在线） |
| ② **整段复读** | 一整段话反复出现（光看单 token 看不出来） | **serve 层可选守卫**：`reasoning_loop_recovery` |
| ③ **纯工具轮空壳** | 连续多轮 assistant **只发 `toolCall`、`text` 为空**，工具结果把上下文撑爆 | **平台护栏**（见 `01` 册）＋ 每轮给工具结果限长 |

> 还有一类**长得像卡死、其实不是循环**：**看门狗开火**（§4）—— 它的形状是"请求直接作废"，不是"输出重复"。

---

## §2 ②整段复读：serve 层的 `reasoning_loop_recovery`

**开关写在 `strata-<model>.json` 里**（默认 `false`）：

```json
"reasoning_loop_recovery": "stop"      // false(默认) | "stop" | "recover" | true(=recover)
```

**它怎么判**（常量是源码里的，照抄）：

| 常量 | 值 | 含义 |
|---|---|---|
| `LOOP_CHECK_EVERY` | **512** | 每 512 个输出 token 看一次 |
| `LOOP_COVERAGE` | **0.25** | 判据：**最近 2,000 个词里，落在"出现过三次的 12 词段落"中的比例 ≥ 25%** |
| `LOOP_HISTORY_WORDS` | **30,000** | 往回数多远（给"看一次"的成本封顶） |

而且**只在干净边界上才动手** —— 代码里的条件同时要求：解析器处于 `reasoning` 态、**没有 tag 被扣住**（`parser.buf` 空）、**没有字符跨 token 被切开**（`parser.pending` 空、`detok.pending()` 空）。
⇒ 这就是"**宁可晚 512 token，也不把标签切一半**"。

**两档行为**：

| 档 | 做什么 | 日志（判据） |
|---|---|---|
| `"stop"` | **就地结束这一轮**（`finish = "length"`） | `[strata] the thinking repeated the same passages (coverage=X.XXX) at N tokens: ended as "length" (reasoning_loop_recovery: "stop" in strata-<model>.json; remove it to turn this off)` |
| `"recover"` | 不结束，**用 low-effort 指令从同一输出继续**（把 xhigh 的指令换掉）；**带图片的请求不做** | 另有一行带 `instruction (reasoning_loop_recovery)` 的打印 |

**上游那条也跟了**（`#1753`）：**一个长词也算循环** —— 早期只看"多词段落"，把"整段写成一个超长词"的循环漏掉了。

## §3 ①逐字复读：引擎自带的单 token 守卫

它**一直在线**，不看思考通道，只看连续重复的同一个 token：`run_len`。收尾时打印：

```
[strata] the reply repeated one token ('X') N times in a row: ended as "length"
         (repeat_stop_tokens in strata-<model>.json; 0 turns this off)
```

⇒ 想关就把它设 `0`；**别把它和 §2 那档混为一谈**（一个看 token，一个看段落）。

---

## §4 看门狗：**看起来像卡死，其实是引擎自己把请求作废了**

- 引擎里有**两个硬编码 20 秒、没有开关可调**的看门狗，语义是"**等 GPU 敲到第 l 层**"。某一层 20 秒没敲钟 ⇒ **看门狗开火，整个请求作废**。
- **不是模型不行、也不是请求不合法**。我们 2026-09-29 那次就是这么栽的：同一个引擎、三份 ctx262k 配置，其中一份 **551 s 被看门狗杀**（其余两份只是慢）。
- 形状：**死在"某一层"，不是"跑到某个 token 数必然死"** —— 所以别用"换个提示词再试"去归因。
- 当时的判决：**本轮不改引擎**（成本不现实）。台账全文见我们的 `坑-引擎20秒看门狗-20260929.md`。

🔴 **同页还有一条更贵的坑**：**杀引擎 ≠ 杀作业**。只杀进程，循环会**立刻拉起新实例**，而新一臂会**静默接到旧服务器上** —— 你以为在测 A，其实在测旧的那个。

---

## §5 判据：怎么知道"治好没治好"（每条都能变红）

| 判据 | 正控 | 负控（能变红） |
|---|---|---|
| 整段复读守卫在跑 | 日志出现 `the thinking repeated the same passages (coverage=…)` | 把 `reasoning_loop_recovery` 删掉 ⇒ **这行不再出现** |
| 逐字复读守卫在跑 | 日志出现 `the reply repeated one token (…) N times in a row` | `repeat_stop_tokens: 0` ⇒ 不再拦 |
| 看门狗没开火 | 请求正常收尾（有 `finish`） | 同一配置重现 20 秒空档 ⇒ **请求无 finish 地作废** |
| ③纯工具轮空壳 | 日志里 assistant 轮次**有正文** | 连续 ≥3 轮 `text` 为空且同一工具 ⇒ 算法本身失效 |

> ⚠️ **别用"输出看起来通顺"当判据**（我们吃过：有损改动下散文依然通顺、而分数已经塌了）。

---

## §6 平台侧那一半（与 `01` 册同一套）

- 提醒阈值 `[3,5,8]` 的放大效应：**第 8 次之后永久静默、只提醒不阻断** ⇒ 循环会一直转到上下文爆掉。
- **熔断判据 = 「同参数 + 同失败结果」≥ 3 次**；失败签名 `sha1(结果前 300 字符去数字)`。
- 工具结果**每轮限长 + 去重 + 摘要**；池 < 题面时中段会**静默不可见**（这是另一类"看起来像卡死"）。

---

## §7 未验（不许当结论）

1. `reasoning_loop_recovery` 两档在**本内测包（v3 引擎）**上的实测读数：**我们没在这一版上跑过对照** —— 它来自 serve 层源码与上游提交，**不是本包的实测**。
2. 看门狗那两个 20 秒：**无开关**，能不能通过调度绕开**未验**。
3. ③纯工具轮空壳的**限长/去重阈值**没有定论。
4. `reasoning_budget_tokens: 0` 的语义是"**不设上限**"，不是"关思考"（这条容易读反，客户端 `max_tokens` 给小 ⇒ 正文为空的常见原因）。
