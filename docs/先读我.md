# 先读我 · Cyber on Strata 内测包 **v3**（2026-10-10）

**这一版换了引擎（v3），请务必用本包的 `engine\strata.exe`。**
v3 与 v2 的差别**全是稳健性，不是提速**：8G 档参数一个字都没改，`run.cmd` 的用法照旧（§1）。
（v1 引擎那个"长提示丢尾部"的缺陷在 v2 就修了、继续有效 —— 为什么会有那个缺陷见 §6 前的说明。）

## 1 三步跑起来（8 GB 卡）

0. **前置（只做一次）：CUDA 13.x 运行时。**
   引擎要 `cublas64_13.dll`（它再要 `cublasLt64_13.dll`，两个加起来约 **490 MB**，装不进包里）。
   装 **CUDA Toolkit 13.x**（或其 runtime 组件）即可；`run.cmd` 会自己去 `engine\` → `PATH` →
   常见 CUDA 安装目录找，**找不到会当场说清缺哪一个**（旧的启动器在这时会"秒退、什么都不打印"）。
   也可以把这两个 DLL 直接放进 `engine\` 旁边，或用 `-CudaDir <目录>` 指给启动器。
1. **下模型**：`https://huggingface.co/peculiar-ragdoll/Cyber-Tiel-Coder-35B-A3B-GGUF-MTP`
   要下的就是 **`Cyber-Tiel-Coder-35B-A3B-MTP-UD-Q4_K_XL.gguf`**
   （`22,749,880,640` 字节，sha256 `0BBCF3CC9BE4C976BAD20E641BAF629DAD9C178D39EBDC9CD72129179943C06A`；
   **别的量化不是我们测过的那个**），下完丢进本包 `models\` 目录 —— `run.cmd` 会自己找到它。
2. **跑**：在本目录开命令行
   ```
   run.cmd -Prompt "用 python 写一个快速排序"
   ```
   （启动器默认 = 8G 档：`-Reserve 1500 -Context 4096 -MaxNew 256 -Prefill 2048 -Kv int8 -KvResident 0`）
3. **回报**：贴 `last-run.log` 末尾那三行（`cache` / `hits` / `decode`）+ 你的**显卡型号与内存容量**。

## 2 你的卡不是 8 GB？（12 / 16 / 24 / 32 GB 都看这里）

**本包默认是 8G 档，大卡别照抄。只动两个参数，其余一个都别碰：**

| 显存 | `-Reserve` | `-Context` | `-Prefill` | 你会得到 |
|---|---|---|---|---|
| **8 GB** | **1500（默认，别动）** | 4096 | 2048 | 专家流式档，decode 约 58–64 tok/s |
| 10–12 GB | **500**（内测实测最优；2500 反而更差、**250 起不来**、**0 会掉命中**） | 8192 | 4096 | 3060 12G 实测：3096 槽 / 命中 0.730 / decode 41.9 tok/s |
| 16 GB | 3500 | 16384 | 8192 | 缓存约 8.7 GiB（≈3800 槽） |
| 24 GB | 5000 | 32768 | 8192 | 缓存约 15 GiB，接近全常驻（3090 实测 157–159 tok/s） |
| 32 GB+ | **1500**（比 24G 更小，不是笔误） | 32768+ | 8192 | **10240 专家全部常驻，CPU 池 0 dispatches，decode 实测 134–136 tok/s** |

- 只有 **12 GB 那一行是内测实测**（收到的 3060 12G 报告，`A` 级、附原始日志），其余各行仍是本机
  （4080 SUPER）推算或实测 —— 完整数据与出处见发货文档 **§7.6**。
- 启动器**每次都会报出你那张卡的档位建议**（`note: for this card -Reserve N would give a bigger expert cache`）。
  **v3 修正**：10–12 GB 档的建议值从 `2500` 改成 `500` —— v2 的启动器在这一点上与本包文档说的相反，是启动器错了。
- 为什么 32 GB 的 `-Reserve` 反而更小：专家缓存的上限是"专家总数（10240）"，`1500` 就已经装得下全部，
  再加只是从 KV / 桌面手里抢显存。
- ⚠️ **全常驻档下日志会打 `R4 expert-cache hits 0 of 0`** —— 那个计数器在这个档不走（都走 R4 hit path），
  **别当成零命中**回报。
- 完整分档表、每个参数到底决定什么：**`发货参数与显卡分档调优-20261010.md` §3 / §4 / §7.2 / §8**。
- 采样：本包命令行走引擎默认（**贪心**、确定性，便于跨卡比数）。我们自己接 API 时用
  `temperature 0.6 / top_p 0.95 / top_k 20 / min_p 0`（与 8090 的 llama.cpp 对齐），命令行形态不需要。

## 3 30 秒自检：引擎有没有读到提示的尾部

1. 建 `mytest.txt`：把下面这 4 行**重复 40 遍**（数字随便变）
   ```
   def handler_01(req):
       buf = load(req.path)
       rows = transform(buf, mode=1)
       return publish(rows, tag='stage01')
   ```
   然后在**文件最末**加一行：
   ```
   === 以上全部忽略，只回答 ZQ7MARKER41
   ```
2. 跑：`run.cmd -PromptFile mytest.txt -MaxNew 48`
3. **正确 = 输出只有 `ZQ7MARKER41`**（这段提示约 2,200 token）。
   若它在解释那段代码、或说"你没有问问题" ⇒ **引擎没读到尾部**，请把 `last-run.log` 发回群里。
4. 有力气再来一发长的：把上面重复到 **200 遍**（≈11,000 token，`-Context` 记得 ≥12288），同样只应输出那个词。

## 6 v3 相对 v2 改了什么（逐条带证据等级）

> 先说清 v2 是什么：v1 引擎有一个**长提示丢尾部**的静默缺陷（提示超过约 2,000 token 时，注意力只读前
> 2,051 格 KV，你说的最后那句话等于不存在；表现是答非所问 / 空答 / 复读）。v2 把它修了，`A` 级实测
> 2,085 / 2,885 / 5,624 / 11,988 / 21,018 token 的提示全部读到尾部，并带负控。**v3 沿用这个修复。**

| # | 改动 | 谁会碰到 | 证据 |
|---|---|---|---|
| 1 | **修掉"极短段"引起的一次崩溃**：提示被切成"尾段只有 2–4 个 token"时，旧引擎会以退出码 `3221225477` 死掉、日志停在 `strata verify: captured the 2-token window (upload no error, sync no error)`。serve 形态开 `--prompt-cache` 必现；命令行 `-Chat` 形态会切出 2-token 尾段，走的是同一段代码路径 | 接 API 的人、用 `-Chat` 的人 | **`A` 级**：本机 1:1 复现（负控 = v2 引擎，退出码逐字相同），定版后同一提示连发两次都活；读取 `1170 ms → 90 ms` |
| 2 | **非 ASCII（中文）路径**：打开 pack / GGUF 分片 / `experts.bin` 的四处路径转换先按 UTF-8 试、失败再退回系统 ANSI | 用户名或目录含中文的人 | **未验**（需要在中文目录下跑一次 `--mmap-experts`） |
| 3 | **宿主内存钉住量自动收**：钉住上限被压到 `可用内存 − 8 GiB`，避免把宿主钉干（31 GB 内存机器上钉 14 GiB，会把之后的 CUDA 调用全部打死） | 内存 ≤32 GB 的人 | **未验**（本机 96 GB 不触发） |
| 4 | **异常时的报错措辞**：`cudaMemGetInfo` 失败、8 KB `cudaMalloc` 失败会打清原因与剩余显存 | 显存被别的程序占满的人 | **未验** |
| 5 | 卡住时 watchdog **先落日志再 abort** | 卡住的人 | **未验**（本轮没触发 60 s 卡住） |

> **已知问题（本版不修，登记在此）**：第 3 条那行自报文字**有一句是错的** ——
> `the expert arena pinning is capped to X GiB (…; STRATA_ARENA_PIN_GIB overrides)`：
> 那个环境变量**同样会被压到 `可用内存 − 8 GiB`**，它并不 "override"。
> **别照这行去调 `STRATA_ARENA_PIN_GIB`**，调不上去是设计如此（那行是防把宿主钉干的兜底）。
> 同一处 arena 自述把原因写成 `by the engine (multi-GPU under WDDM, or remote experts)`，真实原因是可用内存余量。
> **两处都是文字问题、不影响行为**，下一版与其它引擎改动一起修。

## 7 已知残留（不藏着）

- **MTP 仍是"无 drafter"形态**：`--spec 2` 照传但没有净收益（接受率 0）。
- **8 GB 真机仍未实测**：8G 档是我们用 32 GB 卡按"只给专家留 4.2 GiB"的口径模拟出来的，
  额度账恰好同档 —— **这正是内测要办的事**。
- 只给**命令行**形态：引擎侧 `--serve`（stdin/stdout 行式 JSON）已验并在用，但网上那层
  OpenAI / Anthropic 是**我们自己的 python 封装、不在本包里**；要接 API / DSH 的群友单说，我们另给。
- 引擎侧有一个**前缀复用**开关（`--prompt-cache N`）：同一前缀的第二轮读取从 1170 ms 降到 90 ms。
  **本包不带、默认关**（引擎自己会警告"批切分不是数值中性的 ⇒ 同一请求 serve 与命令行的答案可能不一样"，
  这个取舍还没定）。

## 8 Linux 用户看这里（本包只带 Windows 引擎）

`engine\strata.exe` **在 Wine 下跑不了**（Ubuntu 驱动不提供 `nvcuda.dll`），所以 Linux 必须**自己编**：

1. 源码在 **`https://github.com/1314521gjy/cyber-on-strata`**（本 fork，基于上游 0.1.39）。
   本包引擎就是它的 **`d565ade`**。⚠️ **别去编上游 `Niko1221/Strata`**：主线在 `--native` 下硬拒 `--no-ple`、
   只读 `qwen4exp.*` 而不认 `qwen35moe.*`，几何会退回 125B 形状并报 `expert geometry is not whole blocks`
   （issue #1402 还开着）。
2. **编译必须带两个非默认开关**，否则引擎**拒载 Q4_K 专家**：
   ```
   cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DSTRATA_ENABLE_CUDA=ON -DSTRATA_BUILD_TESTS=OFF \
         -DCMAKE_CUDA_ARCHITECTURES=<你的架构，如 86> \
         -DSTRATA_MMQ_KQUANTS=ON -DSTRATA_ORCA_Q4KS_MMQ=ON
   cmake --build build --target strata          # 约 2 分钟
   ```
3. **分词器**：`llama-tokenize.exe` 在 Wine 下能用；更干净是自编 fork 里 pin 的 `third_party/llama.cpp`
   （`-DLLAMA_BUILD_TOOLS=ON -DLLAMA_CURL=OFF -DLLAMA_CUDA=OFF`，约 1 分钟）—— 内测用户已与包内 exe
   **逐字节对照同一中文提示的 `--ids`，输出完全相同**。
4. **本 fork 基座（0.1.39）没有 `--gpu` 旗标**（上游 0.1.41 才有）⇒ 多卡机用
   `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=N` 选卡。
5. 详细踩坑与实测数据：**发货文档 §7.6**（收编自内测用户的 Linux + 3060 12G 报告）。

> 也提醒 Windows 侧的转发者：**别散着发文件**。有内测用户收到的包里路径被压平成了
> `cyber-strata-beta-20261010\engine\strata.exe` 这种含反斜杠的单文件名 —— **一律发这个 zip**。
