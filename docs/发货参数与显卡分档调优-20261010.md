## §0 一句话

**一张 8 GB 显存的显卡 + ≥32 GB 内存，可以把 Cyber-Tiel-Coder-35B-A3B（35B 总参 / 约 3B 激活的 MoE，Q4_K_XL，22.7 GB）跑起来**：专家权重**流式**（常驻内存、按需上卡），KV **可弹性**（长上下文时可把 KV 压位宽或挪出显存），未命中的专家由 **CPU 池**就地算。

本机（32 GB 卡）**实测**：decode **57.7–63.5 tok/s**、prefill **1736–2203 tok/s**、专家缓存命中率 **0.7794**。

### 1.2 结构上成立、但**没有在 8 GB 卡上实测**（`D` —— 内测要做的第一件事）

- **额度账**：引擎自报本机 `28.20 GiB free`，而整卡 32760 MiB ⇒ 非缓存消耗 ≈ **3.79 GiB**（常驻权重 + 上下文 + 激活 + CUDA 上下文）。
  ⇒ 一张 **8192 MiB** 卡的非缓存消耗同量级时，**可用额度 ≈ 8192 − 3880 ≈ 4300 MiB ≈ 4.2 GiB** —— **恰好等于我们现役配置给专家的 4.20 GiB**。
  ⇒ **结论：本机读数与"8 GB 卡"是同一档额度，方向上可外推；但"没在 8 GB 卡上跑过"这句话必须说。**
- **内存是硬前提**：引擎要钉 **19.68 GB** 宿主银行，且依赖 OS 文件缓存持有 21.2 GiB 模型 ⇒ **建议 ≥32 GB 内存，48–64 GB 更稳**。内存不够走 `--mmap-experts` / `--resident-experts`（引擎自带的低内存档），但**冷读会慢约一倍**（源码注释自报 71.97 vs 34.78 ms/token，`D`）。
- **显存带宽随卡走**：本机 GPU 地板 = **7.35 ms/token**（≈136 tok/s 上限）。这个数**绑在卡上，不能外推** —— 慢卡的瓶颈会从 CPU 池转移到 GPU 地板。

## §3 发货参数

### 3.1 基准 argv（本机验证过的那一套，`A` 级）

```
strata.exe ^
  --pack   <pack目录>\iq-native ^
  --native <模型>.gguf ^
  --no-ple ^
  --tokens-file <prompt的token id 文件> ^
  --expert-profile <profile>.bin ^
  --expert-cache auto ^
  --vram-reserve-mib 24568 ^
  --prefill 2048 ^
  --max-context 4096 ^
  --max-new 512 ^
  --kv k8v4 ^
  --spec 2 --suffix-draft 0 --mtp-max-t 1 ^
  --pool-workers 6 --pool-affinity all ^
  --stats
```

> `--no-ple`：Cyber **没有 PLE n-gram 表**，必须显式消融（否则引擎会索要 `--ple-gguf`，而它会静默改变下游所有数字）。
> `--stats`：发货**必须带**，它是内测回报的唯一机器可读来源。

### 3.2 必须随机器变的参数（**发货的核心就在这一张表**）

| 参数 | 它到底决定什么 | 发货规则 | 本机值 |
|---|---|---|---|
| **`--vram-reserve-mib N`** | **从专家缓存里扣掉、留给 KV/激活/桌面的显存**（`缓存 = free − reserve`） | 🔴 **这是唯一必须按卡改的参数**。判据线是引擎自己打印的那一行：`expert cache auto: X GiB free, Y MiB reserved -> N slots`。**先把 reserve 设小，看它报多少槽，再往上加直到留够 KV。** | 24568（**故意的限流值，8 GB 卡绝不能用**） |
| `--max-context N` | KV 容量。4k 时 KV ≈ 100 MB 级（可忽略）；越长越吃显存 | 8 GB 卡建议 ≤8192 起步；要长上下文就配 `--kv` 压位宽 | 4096 |
| `--kv fp16\|int8\|q4_0\|k8v4` | KV 位宽：int8 减半、q4_0 再减半、k8v4 = INT8 K + 旋转 Q4_0 V | 显存紧就 `int8`；极端紧就 `k8v4`（有精度代价，**我们没测过** ⇒ `D`） | 默认 fp16 |
| `--kv-resident N` | KV 流式：每层只留 N 格在显存，其余放**钉住的宿主内存**，腾出的显存给专家槽 | 🔴 **v2 更正：一律 `0`（关）**。它不是"对我们无效"，而是**会丢上下文**：没被做成常驻的 cell 在核心里被**直接 mask**（`qsa_decode_attn.cu`：`page = -1 ⇒ score = -FLT_MAX`），注意力只看得到窗口内的 cell；而且 `20480` 会卡住**提示读取**（实测：21,385 token 的提示只读了 18,432 就 0 输出）。详见 **§7** | **0** |
| `--prefill CHUNK` | 预填分块；`auto` = 能借多少缓存借多少（上限 8192） | 显存富余用 `auto`；紧就用 2048 | 2048 |
| `--pool-workers N` | CPU 专家池线程数（默认 0 = 物理核 −1） | 本机 6 与 4 **同带（NO SIGNAL）**⇒ 别指望它；按物理核数走 | 6 |
| `--pool-affinity all\|auto\|p-cores` | 混合核（大小核）CPU 的绑核 | 12/13/14 代 Intel 用 `auto`；纯大核或 AMD 用 `all` | all |
| `--expert-cache auto` | 按 `free − reserve` 自动定槽数 | 发货一律 `auto`（写死槽数只用于实验） | auto |
| `--expert-profile P` | **静态预填 —— 命中率的主要来源** | **必须带**。引擎 help 自述：不带 profile 的默认策略实测只有 **2.97%** 命中 | 带上 |
| `--mmap-experts` / `--resident-experts` | 放弃钉住银行，退回 mmap（低内存档） | 内存 < 32 GB 才用；**冷读约慢一倍**（`D`） | 未用 |
| `--spec 2 / --mtp-max-t 1` | MTP 投机窗 | 本机 MTP **判**冻结（接受率 0.55 但 decode 仍输）；**发货先按 `--spec 2` 走，别开更大窗** | spec 2 |
| `--vram-elastic` | serve 模式：专家缓存分段，运行期可把显存还给别的程序 | 只在 `--serve` 下有意义，**我们未验** | 未用 |

**发货默认值建议**（把上表钉成一个"能抄"的默认）：

```
--expert-cache auto  --prefill 2048  --max-context 4096  --max-new 512
--spec 2 --suffix-draft 0 --mtp-max-t 1  --pool-workers 0 --pool-affinity auto
--vram-reserve-mib <按卡填：见 §4>  --stats
```

## §4 分档调优名单（按显存分档）

**用法**：先按本档的 reserve 起跑，**看引擎报的那一行**，再按"调优方向"微调。
**槽数估算口径**：本机 4.20 GiB ↔ 1960 槽 ⇒ **约 2.25 MB/槽**（`D`，用本机读数折算）。**预计 decode 一律不给绝对值** —— 它同时受 GPU 带宽（随卡）与命中率（随槽数）支配，编一个数出来就是假绿。

| 显存档 | 非缓存消耗后可用（估） | **建议 `--vram-reserve-mib`** | 预计槽数（估） | 调优方向 | 必做自检 |
|---|---|---|---|---|---|
| **8 GB**（8192 MiB） | ≈4.3 GiB | **800–1200**（**本包默认发的是 `1500`**，理由与账见 §7.2 / §7.3；到不了就按本行回退） | ~1300–1500 | 槽数不够就压 KV（`--kv int8`）；`--max-context` 先 ≤8192 | 看 `free/reserved/slots` 三数；确认**没有**"分页/爆显存" |
| **10–12 GB** | ≈6–8 GiB | **500–1500**（**v2 起按 3060 12G 实测下修**，见 §7.6；原表写的 `1500–2500` 已被实测推翻） | ~2000–3200 | 命中率会明显好于 8 GB 档；**先把 reserve 往下试** | 同上 + 记命中率 |
| **16 GB** | ≈12 GiB | **2500–4000** | ~3500–5500 | 上下文可以放到 16k–32k（KV 还扛得住） | 同上 |
| **24 GB** | ≈20 GiB | **4000–8000** | ~5500–9000 | 接近"全常驻"；试 `--max-context 32768+` | 同上 |
| **32 GB** | 28.2 GiB | **1500**（全常驻）或 **24568**（限流档） | **10240 / 1960** | 全常驻档 CPU 池**完全不工作**，decode **134–136**；限流档 CPU 池 5.4 ms | 两条都测，回报两条 |
| 多卡 | — | `--peer-device N` / `--expert-cache-device1..3` | — | 引擎支持第二卡当专家层（P2P） | **我们完全没验**（`D`） |

**两条通用调优顺序**（先便宜后昂贵）：
1. **先把 reserve 往下调**（每次 1000 MiB）直到引擎报的槽数不再涨或 KV 吃紧 —— 这一步通常比任何代码优化都值钱。
2. 再看 **命中率**（`R4 expert-cache hits`）。它 100% 由 **profile 排名 × 槽数** 决定（缓存**永不收人**：`0 admitted / cache 100% full`）⇒ 槽数不够时，**换 profile 比调别的东西都有效**。

### §4.1 高显存显卡：怎么"解除 8 GB 限制"

**只有一个旋钮：`--vram-reserve-mib`**（= 从专家缓存里扣掉、留给 KV/激活/桌面的显存）。它越小，专家缓存越大。

- 本包默认 `-Reserve 1500`；卡大的话可以继续往下调（500 甚至 0）。
- 规则：`缓存 = 引擎自报的 free − reserve`；`槽数 ≈ 缓存 MiB / 2.25`；**当缓存 ≥ 18.32 GiB ⇒ 10240 个专家全部常驻显存**，此时 CPU 专家池完全不工作（日志里 `0 dispatches`），decode 实测跳到 **134–136 tok/s**。
- 各档估算（`free ≈ 显存总量 − 3.8 GiB`，本机实测的 3.8 GiB 含常驻权重/CUDA 上下文/激活）：

| 显存 | free（估） | `-Reserve 1500` 时的缓存 | 预计档位 |
|---|---|---|---|
| 8 GB | ~4.3 GiB | ~2.8 GiB | 流式（约 1250 槽） |
| 12 GB | ~8.2 GiB | ~6.7 GiB | 流式（约 3000 槽） |
| 16 GB | ~12.2 GiB | ~10.7 GiB | 流式（约 4800 槽） |
| 24 GB | ~20.2 GiB | ~18.7 GiB | **全常驻** |
| 32 GB | **28.20 GiB（实测）** | 26.7 GiB | **全常驻**（实测 10240 槽 / 18.32 GiB） |

- ⚠️ **全常驻档很快，但它不是本项目的验收形态**（验收基准是流式档）。两种都跑一遍、分别回报，价值最大。
- 想**强制回到流式档**（复现我们的基准数）：把 reserve 调到 **24568** —— 这正是我们测流式档时用的值。

### §4.2 可用显存比标称小（比如 8 GB 卡只有 4 GB 能用）

**先读引擎那一行，它是唯一的真话：**

```
expert cache auto: X GiB free, Y MiB reserved -> N slots
```

`X` = 加载完常驻权重后**真实可用**的显存（桌面、浏览器、其它程序全都已经从这里面扣掉了）⇒ **不要拿标称显存去推**。

调整规则，按优先级：

1. **先关掉别的占卡程序**（浏览器硬件加速、壁纸引擎、其它模型/游戏）。
2. `X` 小 ⇒ 缓存自动变小 ⇒ 槽数变少 ⇒ 命中率变低 ⇒ CPU 池更忙 ⇒ **变慢，但不会崩**。这是**连续降级**，不是坏掉。
3. 若出现**显存不足 / 分页 / 闪退**：把 `-Reserve` **调大**（留更多余量给 KV、激活与桌面）。⚠️ 方向别搞反：**reserve 大 = 更安全 = 更慢**。
4. 同时把 `-Context` 调小（KV 更小），或按 §4.3 用 `k8v4` / `q4_0`。
5. 内存不足（不是显存）走 `--mmap-experts` / `--resident-experts`（引擎自带的低内存档），代价是冷读约慢一倍。

**最小可用显存我们没有实测**（手上只有 32 GB 卡）。机制上缓存可以小到接近 0（全部专家交给 CPU 池），但会很慢。**请 4 GB 可用档的测试者把那一行原始数字发回来** —— 这是我们唯一能补齐这条曲线的方式。

### §4.3 KV 放在哪、默认多大、什么精度

**放哪**：默认**全部在显存里**，占的正是 `--vram-reserve-mib` 留出来的那块（与专家缓存互斥：reserve 大 ⇒ KV 宽松、专家缓存小）。

**能不能挪到内存 —— 能，已实测（`A` 级）；但 v2 起我们**不发货这个配置**：`--kv-resident N` = 每层留 N 格在显存（下限 **20480**），整份 K/V 放**钉住的宿主内存**，腾出的显存还给专家槽。

> 🔴 **v2 更正（2026-10-10）：本节策略会丢上下文，且 `20480` 会卡住长提示读取 ⇒ 发货一律 `0`，见 §7。**
> 下面的读数**是真实的历史数据、保留不动**（它们是当时测的），但**不要再照它配置**：
> 省下 0.23–2.11 GiB 显存的代价，是**注意力只看得见窗口内的 cell**。

- `int8` 的数值**与 fp16 一致**（第 7 位同为 `9167`）⇒ **我们在 fp16 下建立、并对过外部 llama.cpp 参考的那套正确性锚继续有效**；
- `k8v4` / `q4_0` 都会把第 7 位改成 `21` —— 它**恰好是参考值**，但那是"**近并列翻转**"点，**不能当质量提升宣传**；

**省多少**：4k 上下文下 KV 本人只有 86 MiB，省不出多少；**长上下文才回本** —— 128k 时挪进内存约腾出 **2.1 GiB 显存**（内存代价 fp16 2.5 GiB → int8 约 1.25 GiB）。

**三条诚实登记**：① 挪内存的**速度代价未定论**（每步要从钉住内存取 K/V，走 PCIe）—— 本批 decode 读数 n=1、同配置散布已知 ≥5.75 tok/s，**判不了**；② `-Kv k8v4` 与 `--kv-resident` 的组合**引擎拒绝**（help 明写），所以默认用 `int8`（启动器检测到这种组合会自动改 fp16 并提示）；③ **v2 新增：它会丢上下文**（非驻留 cell 被 mask），且 `20480` 会卡住长提示读取 ⇒ **发货一律 `0`**，见 §7。

## §7 v2 修订记录（2026-10-10）—— **本版与 v1 的差别全在这**

### 7.1 换了引擎：修掉一个"长提示丢尾部"的静默缺陷

**症状（就是你会在群里看到的那种）**：提示一长（> 2,000 token 左右），模型的回答就变成
"我先看一下环境 / 你没给问题 / 这是 47 段重复的代码"这类**答非所问**，或者干脆空答、复读。
短提示一切正常 —— 所以它很容易被当成"模型不行"或"量化不行"。

**根因（已定位到行）**：引擎把**上游靶子的选择预算 2,048**（`attention.indexer.top_k`）当成了本模型的；
`qsa_selection_width() = min(n_kv, 2048 + 4 - 1)` ⇒ **恒 ≤ 2,051 格**。
于是 `n_kv ≥ 2,052` 时**注意力只读前 2,051 格 KV**，尾部（也就是你真正问的那句话）等于不存在。
本模型自己的预算是 **262,144**（= 整个上下文，从不剪枝）。

**修法**：预算改成模型自己的口径 ⇒ 选择退化为**恒等** ⇒ 稠密全注意力，`width = n_kv`。

**判据读数（`A` 级，同机）**：提示末尾放一句"忽略以上全部，只回答 `ZQ7MARKER41`"：

| prompt tokens | v1 引擎 | v2 引擎 |
|---|---|---|
| 2,045 | ✅ | ✅ |
| **2,066 / 2,085** | ❌ 丢尾 | ✅ |
| 2,885 / 5,624 | ❌ | ✅ |
| 11,988 / 21,018 | ❌ | ✅ |

**负控（同一二进制、只把预算拨回 2,048）**：2,085 与 2,885 立刻变红，模型自己说
*"There's no actual question. The user just pasted code."* ⇒ 因果确定。

### 7.6 收编：内测用户（Linux + RTX 3060 12G）的分档实测 —— **12 GB 行的推荐值按此下修**

> 来源：内测用户 2026-10-09/10 提交的《Cyber on Linux 移植 + RTX 3060 12G 分档实测报告》
> （`A` 级、附原始日志与脚本：`log-gpu2-streaming.txt` / `log-gpu2-32k-kvresident.txt` /
> `log-gpu0-fullresident.txt` / `cyber-run.sh` / `build-engine.sh`）。
> 引擎为 fork `1314521gjy/cyber-on-strata` @ `04704be`（**即 v1 引擎那一代**）。

**12 GB 档（RTX 3060 12G，`free = 7.13 GiB`，卡上另有桌面与视觉进程）**：

| `--vram-reserve-mib` | 槽数 | 命中率 | CPU 池 ms/token | decode tok/s |
|---|---|---|---|---|
| 2500 | 2185 | 0.6599 | 6.72 | 37.8 |
| 1500（v1 发货默认） | 2641 | 0.6972 | 6.11 | 39.8 |
| **500（本机最优）** | **3096** | **0.7299** | **5.40** | **41.9** |
| 250 | — | — | — | ❌ **起不来**：`verify: the device arena (43 MiB) does not fit` |
| 0 | 3324 | 0.7064 | 5.81 | 41.3（**掉命中**：提示路径 `borrows 698 cache slots` 借走专家槽） |

⇒ **三条要写进推荐里的话**（其中两条是这次实测才有的）：
1. **12 GB 的推荐从 1500–2500 下修到 `500–1500`**；reserve 每降 1000 ≈ 槽 +450、命中 +约 3 个百分点、decode +约 2 tok/s。
2. **下界不是 0，而是"verify arena 报 `does not fit` 就回退一档"**（250 直接起不来）。
3. **`0` 反而不划算**：少留 reserve ⇒ 提示路径要借更多专家槽（日志 `borrows 698 cache slots`），命中率从 0.730 掉到 0.706。
- 长提示（1,486 token）：prefill 315.6 tok/s、decode 46.6、命中 0.778、CPU 池 4.65 ms/token。
- 与发货方（4080 SUPER 57.7–63.5）的差距：带宽 360 vs 516 GB/s + 槽少 27% + 该机 CPU 无 AVX-512 ⇒
  **瓶颈转移，与 §R2 预测一致**，不是引擎问题。

**24 GB 档对照（同机 3090）**：报 `20.85 GiB free, 1500 MiB reserved -> 9043 slots`，实填
`10240 / 18.32 GiB`、**CPU 池 0 dispatches**、decode **157–159 tok/s**、prefill 1898 tok/s。
⚠️ **全常驻档下 `R4 expert-cache hits` 会打 `0 of 0`（该计数器在这个档不走，都走 R4 hit path），
别把 0/0 读成零命中** —— 回报时请注意。

**⚠️ 一份必须打上标记的旧结论**：该报告在 12 GB 卡上确认"`--kv-resident` 对 Cyber 有效"（§三 R3）。
**那是对的"机制有效"，但不是"应该用它"**：它的判据是日志出现 `KV streaming: … pinned RAM` 且输出人工看着正常，
而**那次实测的提示只有 1,486 token** —— 旧引擎的截断阈值是 2,051，所以窗口外的 cell 被 mask 这件事
在那批读数里**根本不可能暴露**。本版已把 `--kv-resident` 一律改为 `0`（§7.2 / U8）。

**Linux 用户怎么办 —— 收编自该报告的七条**（逐条都已核对）：
1. **`strata.exe` 在 Wine 下跑不了**（Ubuntu 驱动不提供 `nvcuda.dll`，`cublas64_13.dll` 导入失败）⇒ **必须自编译**。
2. **上游 `Niko1221/Strata` 主线不支持本模型**（在 `--native` 下硬拒 `--no-ple`；只读 `qwen4exp.*`、
   不认 `qwen35moe.*` ⇒ 几何退回 125B 形状 ⇒ `expert geometry is not whole blocks`；issue #1402 仍开着）
   ⇒ **只能从本 fork 编译**：`https://github.com/1314521gjy/cyber-on-strata`。
3. **编译必须带两个非默认开关**：`-DSTRATA_MMQ_KQUANTS=ON -DSTRATA_ORCA_Q4KS_MMQ=ON`
   （默认 OFF 时引擎**拒载** Q4_K 专家）。完整可用配置见该报告的坑 4，约 2 分钟。
4. **分词器**：`llama-tokenize.exe` 在 Wine 下能用；更干净是自编译 `third_party/llama.cpp` 的
   `llama-tokenize`（`-DLLAMA_BUILD_TOOLS=ON -DLLAMA_CURL=OFF -DLLAMA_CUDA=OFF`，约 1 分钟），
   该用户已与包内 exe **逐字节对照同一中文提示的 `--ids`，输出完全相同**。
5. **fork 基座（0.1.39）没有 `--gpu` 旗标**（上游 0.1.41 才有）⇒ 多卡机用
   `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=N`。
6. **卡被别的程序占着不崩**：只少槽、连续降级（§4.2 得到确认）。
7. **别散着发文件**：该用户收到的包里路径被压平成了 `cyber-strata-beta-20261010\engine\strata.exe`
   这样的**含反斜杠单文件名** ⇒ **一律发 zip/tar**（本包就是 zip）。

## §8 v3 修订记录（2026-10-10）—— **本版与 v2 的差别全在这**

> 本版**没有动任何发货参数**：8G 档仍是 `-Reserve 1500 -Context 4096 -MaxNew 256 -Prefill 2048
> -Kv int8 -KvResident 0`（§7.2），分档表（§7.2 / §7.6）也不变。改的是引擎的**稳健性**与启动器的**两处错**。

### 8.1 换了引擎（`216D04F7…` → `7D615BDD…`）：五条，逐条带证据等级

| # | 改动 | 谁会碰到 | 证据 |
|---|---|---|---|
| 1 | **修掉"极短段"引起的崩溃**：提示被切成"尾段只有 2–4 个 token"时（serve 形态开 `--prompt-cache` 必现；命令行 `-Chat` 形态会切出 2-token 尾段，**同一段代码路径**），v2 引擎以退出码 **`3221225477`** 死掉，日志停在 `strata verify: captured the 2-token window (upload no error, sync no error)` | 接 API 的人、用 `-Chat` 的人 | **`A` 级**：本机 1:1 复现（负控 = v2 引擎，退出码与日志尾行逐字相同）；定版后同一提示连发两次都活，读取 **1170 ms → 90 ms** |
| 2 | **非 ASCII（中文）路径**：四处文件打开（pack / GGUF 分片 / `experts.bin` / 无缓冲读）的路径转换改成"先 UTF-8、失败退回 ANSI" | 用户名或目录含中文的人 | **未验** —— 需要在中文目录下跑一次 `--mmap-experts`（可用目录联接，不必复制 80 MB） |
| 3 | **宿主内存钉住量自动收**：钉住上限压到 `可用内存 − 8 GiB`（余量沿用 resident 那条路的 8 GiB） | 内存 ≤32 GB 的人 | **未验**（本机 96 GB 不触发）。来源是回执里"31 GB 机器上钉 14 GiB 把之后的 CUDA 调用全打死，12 GiB 正常" |
| 4 | **异常报错措辞**：`cudaMemGetInfo` 失败、8 KB `cudaMalloc` 失败会打清 `cudaGetErrorString` 与剩余显存 | 显存被别的程序占满的人 | **未验**（要那种机器状态） |

（21k 那次给出正确的 `edit_file` 参数）；`--help` exit 0。

**8G 档的账没变**：这次没有新增常驻显存（改动都在宿主内存与提示切分路径上）。

### 8.2 启动器两处修正（`run.ps1`，不涉引擎）

1. **10–12 GB 档的建议值 `2500` → `500`**：v2 的启动器与 §7.6 的实测结论**相反**（3060 12G 上 500 最优、
   2500 反而更差）——那是启动器错了。§4 总表里的 10–12 GB 行同样下修。
2. **CUDA 运行时预检**：引擎要 `cublas64_13.dll`（+ `cublasLt64_13.dll`，约 490 MB，装不进包）。
   v2 的启动器在缺这两个 DLL 时是"**秒退、什么都不打印**"（`0xC0000135`）；现在会去
   `engine\` → `PATH` → 常见 CUDA 安装目录找（也可 `-CudaDir <目录>` 指定），找不到就**报出缺哪一个**再退出。
3. **zip 里的条目名改成规范正斜杠 + 顶层文件夹**：v2 的 zip 里条目名是反斜杠（`engine\strata.exe`，
   Windows PowerShell 的 `Compress-Archive` 行为，**不符合 ZIP 规范**）—— 某些解压工具会把它当成**一个文件名**
   （§7.6 第 7 条那位群友收到的"含反斜杠单文件名"很可能就是这么来的）。本版改为 `cyber-strata-beta-20261010-v3/engine/strata.exe`。

### 8.3 已知问题（本版不修，登记在此）
